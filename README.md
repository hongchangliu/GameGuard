# GameGuard 0.17

GameGuard 在手机上的显示名称为“应用使用管理”，使用 Android 设备所有者（Device Owner）策略。当前 APK 使用同一签名进行覆盖更新，但已关闭调试并去掉 `android:testOnly`；设备所有者不能再通过测试移除命令删除。

## 第一版行为

- 非黑名单 App 可正常通过应用市场安装和运行。升级自 0.2 时，App 会清除旧版的全局禁装策略。
- 管理员可在手机本机设置至少 8 位密码，修改黑名单需要密码；也可选择单文件 APK 手动安装。
- 管理员按应用名称关键字设置黑名单。旧版本的预设包名规则在更新时迁移为相应名称关键字；同名的不同渠道包按显示名称匹配。系统通过 `setPackagesSuspended` 禁止命中的已安装应用启动。
- Android 标记为“游戏”的第三方应用也会默认禁止运行。管理员可以用密码审核放行，放行的包会作为例外保存。系统拦截弹窗中的支持文案为“请和爸爸联系”。
- 管理员可添加或移除名称关键字；已安装应用立即重新核对。移除关键字后，没有其他规则命中的应用会解除限制。应用名称未知的旧包名规则会显示在页面中，供管理员处理。
- 设备所有者启动带常驻通知的保护服务，运行时实时接收安装事件并核对黑名单。启动 App、重启设备及约每 15 分钟的系统定期任务也会重新核对安装包。
- 可在手机设置中授予“使用情况访问权限”，记录每天切换到前台的第三方应用、前台事件次数和首次/末次时间；报告保留在应用私有存储中，最多 30 天。管理员可在手机上配置 QQ 邮箱地址及 SMTP 授权码，每日将前一天的报告发回同一邮箱，也可输入管理员密码立即发送当天截至当前的记录。授权码由 Android Keystore 加密保存。系统可能延后每日任务；未授权使用情况访问权限或未配置邮箱时不会自动发送。
- 设备所有者策略会阻止卸载 GameGuard；在 Android 11 及以上还会尝试阻止用户清除它的数据和强行停止它。重启广播会重新核对限制和黑名单。
- 管理员可输入密码启用或解除 Android 的 `DISALLOW_FACTORY_RESET` 策略，限制从系统设置恢复出厂设置。默认关闭；无法阻止恢复模式或其他系统外部清除方式。

Android 标准设备管理接口不能按应用名称预先拦截应用市场中的安装。本版允许安装后再按名称关键字禁止运行。游戏类别识别依赖应用提供的 Android 分类，未声明分类的游戏可能漏拦。Android 8 及更新版本不保证向清单注册的接收器发送第三方应用的安装广播，因此改用运行中的前台服务接收安装事件；若系统或用户终止服务，新安装应用可能在下一次定期核对前短暂运行。只支持单文件 APK 手动安装，不支持 App 内多 APK 安装包。MagicOS 10 上的重启行为和多用户或“应用分身”的覆盖范围仍需真机验证。

## 构建

在 Android Studio 打开项目并安装 Android SDK 35，执行 `assembleDebug` 或 Build APK(s)。APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。本项目最低支持 Android 10（API 29）。已有设备从旧版本升级时，可用本地环境变量 `GAMEGUARD_MAIL_ADDRESS` 临时提供旧版的发件邮箱地址；首次启动会将其保存到设备本地配置。不要将地址或授权码提交到仓库。

## 更新与桌面图标

0.3 以后的常规覆盖更新无需解除全局禁装策略。0.8 去除了测试移除入口；如需退回普通个人设备，需通过 Android 正式的设备所有者清理流程或恢复出厂设置，先备份数据。

MagicOS 10 的“设置 > 隐私 > 隐藏应用”可隐藏第三方应用的桌面图标；管理员可输入该功能的密码，从隐藏应用列表重新打开本 App。此设置由系统提供，应用仍可能出现在系统管理页面和搜索结果中。

## 设备所有者测试

不要在日常手机上直接激活 Device Owner，也不要为了测试去删除账户、用户或重置日常手机。先在模拟器或专用测试设备验证。设备应没有其他用户、工作资料和账号；安装 APK 后，再执行：

```sh
adb install -t app/build/outputs/apk/debug/app-debug.apk
adb shell dpm set-device-owner com.gameguard/.GameGuardAdmin
adb shell dpm list-owners
```

在 App 内设置管理员密码并确认黑名单和手动安装流程。若设置 Device Owner 失败，保留设备原状并检查测试条件。
